## 承诺式骨干（4 步）

### S1 文档写得出、留得住——员工在文档树某节点新建文档，写富文本正文（标题/段落/列表/勾选/代码块/图片/@提及其他文档），保存后刷新还在，出现在本组织文档树；能移动/重命名/软删+30 天回收站；整篇可导出 Markdown 拿走

【挂片】文档树 UI（层级 folder/doc；拖拽移动）/ TipTap 编辑器（**跨 app 移植** + staff-hub light 主题 + schema 白名单）/ 文档元数据表（`documents`：id UUID、org_id NOT NULL、parent_id、title、owner_member_id、visibility、deleted_at）+ 正文 JSONB（`content jsonb` 或分块 `doc_blocks`，见判定点）/ 自动保存（防抖落库）/ 软删+回收站+删档二次确认（输入标题）/ Markdown 单档导出端点（数据主权底线）/ 审计行（复用 db_audit 形状，tenant_id NOT NULL）

【分支/判定点】
- **⚠️ 正文存储形态（本路架构级判定之一，呈拍板）**：推荐**整档 ProseMirror JSON 存 `documents.content jsonb` + version int**；分块存（doc_blocks 每块一行）留给 S2 实时协作若走 CRDT 时再评。理由同路③：唯一沿用现成隔离机械断言范式、注入面物理为零、无运行时 DDL
- id 一律 UUID（文档/文件夹），反枚举
- 组织归属一律取 `req.workbenchIdentity.orgId`，绝不从请求体取
- 自动保存失败（弱网/500）必须在编辑器可见并保留本地草稿，禁静默丢失（现状 CustomerListPage 全量重拉掩盖失败，不得继承）
- @提及其他文档：目标文档必须校验同 org + 请求者有权可见（跨企业/无权文档 id → 统一 404，不泄标题）

### S2 多人协作改得动、不打架——多个员工同时编辑同一篇文档时看得到别人在改/改了哪里，冲突时看到提示而不是静默覆盖；断连时降级为单人可编辑并提示

【挂片】协作会话通道（WS 或轮询，见判定点）/ 在线协作者指示（谁在看/在改）/ 冲突检测与提示 UI / 断连降级横幅 / 版本历史最小档（可回看上一版，回滚后刀）

【分支/判定点】
- **⚠️ 协作模型（本路最大架构级判定，呈拍板）**：thin 走**文档级/块级乐观锁 + 冲突提示**（镜像路③ S2 乐观锁，提交带基线 version，不匹配 409+可见提示「该文档被 X 改过，你的改动未保存」，禁静默 last-write-wins）；真·实时字符级合并（Yjs/CRDT）作为**加厚**后刀。待拍板 Q1：主理人「多人协作编辑」的验收底线是「不静默覆盖+看得到冲突」够不够，还是首刀就要 Google-Docs 式实时同步
- 断言：双会话同 version 各提交同文档 → 第二个 409 且库值=第一个；**变异证明**=注掉 version 检查断言必须转红
- 协作通道断连必须可见（横幅+只读降级），禁静默丢改动
- 并发洪峰：同文档 N 人同时改 → 无死锁，乐观锁串行化落库

### S3 文档按权限管得住——文档/文件夹设可见范围与可编辑范围（组织可见 / 指定范围 / 仅自己 三档），权限沿文档树继承；无权的人看不到标题、不出现在树、搜不到、打不开、导不走

【挂片】权限设置 UI（每文档/文件夹选 visibility 档）/ 权限沿树继承的解析器 / 树列表按权限过滤 / 搜索按权限过滤 / 编辑权限校验（可见≠可编辑）

【分支/判定点】
- **⚠️ 三层权限的中间层来源（呈拍板 Q3）**：现有员工目录只有 org+member 两层，**无部门/分组概念**。三档里「指定范围」的中间层落法待拍板：(a) 只做 组织/仅自己 两档，中间层后刀；(b) 中间层=显式指定成员集合（不引入部门表）；(c) 新建部门/分组表（重）。推荐 (b)：不引入新组织结构，先满足「私密/指定人/全组织」
- **⚠️ cross-tenant vs intra-org 两层隔离**：跨企业由 Gate G0 workbenchAuthGuard 兜底；本步管的是**同组织内**的文档级 ACL。读路径二次校验：展开树/搜索/打开/导出/@提及五处都要过权限过滤
- 反枚举：无权文档与不存在文档统一 404、同文案、同响应形状
- 权限查询失败 → fail-closed（503 不静默降级为「可见」）
- 权限沿树继承 vs 单档覆盖的优先级规则（子档显式设权覆盖父档继承）需定义

### S4 AI 一等公民读得到、写得回——员工能让 AI 就本组织文档答问/摘要（带出处），也能让 AI 把内容写回文档成草稿；AI 的读与写**受同一权限约束**，且检索到的文档正文里的指令不被当作系统指令执行（投毒防护）

【挂片】文档进 AI 检索域的索引（与路③排除相反，见 Gate/判定点）/ 带出处的问答/摘要 / AI 写回草稿（插入为可见的「AI 草稿」块，人工确认后成正文，不自动发布）/ 自有 LLM 接线（line 级横切件 AI 助手层，复用路①）/ 投毒防护（检索正文以数据分隔，输出不自动执行）

【分支/判定点】
- **⚠️ 检索域纳入决策（本路命门，呈拍板 Q2）**：路②文档是第一类应进 QA 检索域的内容（经验与文档打通）。但纳入即打开投毒面。必须定义：① 检索只召回**请求者有权可见**的文档（权限过滤前置于检索，禁先召回后过滤泄标题）② 文档正文里的「忽略以上指令/你现在是…」不被当系统指令（分隔+来源标注+输出不自动落库）③ AI 写回的内容标注 AI 来源+人工确认闸，不自动成为别人检索到的「事实」（防投毒二次传播）
- **⚠️ AI 写回的越权面**：AI 写回走同一 workbenchAuthGuard + S3 权限校验，绝不以「系统身份」绕过权限写别人的私密文档
- 断言：A 企业/无权成员的文档绝不出现在 B 的问答上下文（构造投毒文档验证跨企业+intra-org 双向不召回）；正文注入指令集（「ignore previous」「system:」）→ AI 输出不执行、答案带出处
- 软承诺（标注「软」）：摘要「抓得住要点」「答得出处对」→ eval 集 + LLM judge + 人工抽样

## 路级断言（塞不进单步）
- 硬：cross-tenant 隔离在 文档/文件夹/正文/@提及/检索域 五层全部成立（A15 范式+变异）
- 硬：intra-org 权限三档在 树/搜索/打开/导出/AI 检索 五处全部过滤（无权=统一 404）
- 硬：windows_cloud 真浏览器 E2E 全链：建文档→写富文本→存→刷新还在→第二人协作→冲突 409 提示→设仅自己→第三人打不开/搜不到→AI 问答带出处→AI 写回草稿→人工确认；接线三件套（spec 进 workflow 清单+guard 文件名列表，smoke 进 smoke-baseline.txt，聚合进 required check）
- 硬：投毒文档（含「ignore previous」）不改变 AI 对其他问题的回答，且绝不跨企业/越权被召回（变异：删投毒过滤断言报红）
- 软（定量）：3 名非技术员工，无文档，20 分钟内独立完成建文档+写 200 字+分享给同事协作，2/3 达标

## 待拍板问题（拿不准的不硬填）
- **Q1 协作模型底线**：「多人协作编辑」thin 首刀=乐观锁+冲突提示（不静默覆盖）够不够？还是必须首刀就上 Google-Docs 式实时字符级同步（Yjs/CRDT，重）？（推荐：thin 乐观锁，实时 CRDT 加厚）
- **Q2 检索域纳入范围**：路②文档进 AI 检索域（与路③相反）——全部文档进，还是员工显式标「可被 AI 检索」才进？投毒防护底线以哪条为准？
