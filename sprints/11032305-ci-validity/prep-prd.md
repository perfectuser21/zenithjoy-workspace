## 验收行为

1. 安全审计、登录态检测、状态回写、同步或通知失败时，调用方获得非零退出；未知状态不能写成正常。
2. 所有受影响 required 聚合检查首先验证变更检测成功和布尔输出，再检查实际被选中的业务任务；已执行任务失败不能被错误路由覆盖。
3. PR、push、merge_group 使用事件的真实 SHA；Git 差异不可读必须失败。共享锁、workspace 清单及检查脚本变动会触发实际消费者。
4. Core Regression 执行真实本地业务回归；破坏真实实现后门禁必红。真实服务/设备验收仍使用原 L4，不以离线回归替代。
5. L2 解析真实登记表，拒绝结构、路径、重复、符号链接越界与遗漏错误；待接入库存不冒称已执行。
6. 投影漂移检查不能先重生成修平被验物；有价值的孤儿回归接入正式命令，页面回归执行真实组件。

## 实施与验证

- 独立 worktree，不携带主工作区已有暂存变更。
- 多轮并行处理，先运行永久反例见红，再修改实现；作者以外交叉复核，并用故障注入校验测试检测能力。
- 对受影响检查运行完整 workflow 合同套件、产品图/验收套件、Staff Hub 全套，以及 Dashboard 全套和现行覆盖率阈值。
- 固定业务 skill 来源恢复后才运行相关检查；沙箱监听限制与安装树混用分别复验，不能冒充代码故障。
- 开 PR 后跟踪其真实 CI；不将本地绿灯表述为远端通过。

## 队列边界

L1 和 Smoke 的逐 PR 元数据/基线删除理由尚无可验证队列等价证明。merge_group 订阅后明确拒绝，而非缺少 required 信号或借跳过的子任务通过。此项不宣称完整启用 merge queue。
