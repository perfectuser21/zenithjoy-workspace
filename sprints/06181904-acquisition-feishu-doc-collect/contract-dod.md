# Contract DoD — Sprint: 客户智能获客 飞书企业信息文档 + 扩词 + 中台采集闭环（Path2 Step4）

**范围**: 绑飞书自动建企业信息 docx(存 doc_token) → 获客页采集(前置校验+读文档扩 3 词,可手输覆盖,降级兜底) → 派单 → fake-agent 回报抖音号(断点续抓/取消/partial) → 按 (tenant_id,sec_uid) 去重落 DB(SSOT,昵称弱去重) → 写飞书 Leads(失败标待补写飞书) → 获客页 7 态+计数+失败原因+抖音号跳主页 + 10min 超时兜底 + 双租户隔离。真机真抓(xian-pc 抖音 CDP)手验另附,不入自动 E2E。
**大小**: L

> [BEHAVIOR] 在 evaluator 本机跑（mode A），依赖 env：`API_BASE`（中台 localhost）、`DB`、`FEISHU_API_BASE`（fake-feishu）、`FAKE_LLM_BASE`（fake openrouter，= OPENROUTER_BASE_URL）、`SMOKE_TOKEN`。每条 `source` 共享 seed.sh 并自带最小 seed，独立可跑。
> [BEHAVIOR:E2E]（获客页 UI，mode B）走 windows_cloud `e2e-verify.ps1` + Playwright，见 contract-draft.md ## E2E 验收。
> 状态值约定：`acquisition_collect_tasks.status` ∈ pending/running/cancelling/cancelled/done/partial/failed（7 态，CHECK 约束）；`acquisition_leads` 去重键 (tenant_id,sec_uid)，sec_uid 缺失按 (tenant_id,nickname) 弱去重。
> `error_code` 字段统一承载失败/部分原因：partial→`video_insufficient`/`comments_closed`/`zero_comment`；failed(抖音侧)→`DOUYIN_RISK`/`DOUYIN_CAPTCHA`/`DOUYIN_NOT_LOGGED_IN`（report body 传入，字面落库，区分原因）。
> 超时与离线规则：sweep-timeouts 仅把 **stale running**（started_at 早于 NOW-10min 仍 running）转 failed/partial（PRD「不假死在 running」）；**pending**（Agent 离线，未被领取）一律保留不丢，等 agent 上线续抓，sweep 不得动它。
> 字段名为法律：成功 `{success,data,timestamp}`、错误 `{success,error:{code,message},timestamp}`；扩词 `data.keywords[].word/.source`，禁用 `keyword/words/result`；查状态 `data.status`（7 态），禁用 `state/videos/count`。
> 本合同对 PRD NFR 取舍：NFR「单抖音号每天 ≤3 次采集」(同 sec_uid 24h 采集次数上限) **本 sprint 不做**，移出本合同范围——它是跨任务/跨时间的 anti-ban 限流，与 PRD「不在范围内」已声明的「跨任务去重」同类，按 CLAUDE.md 第一刀纪律「加厚(限流守卫)必须有真实封号/限流证据驱动」推迟到加厚阶段。详见 contract-draft.md ## 范围限定。
