# PrepPRD：手机详情页补今日进度 + 待办队列 + 失败原因人话化

Brain task `3bbdb025-ceb4-40a1-90f9-56efec86dc48` · GP-Anchor: `line02/keyword_acquisition keep-green`

## 主理人原话

> 「这个手机安排了 50 个任务，今天已经执行了 25 个任务了。我下面还有哪些任务是我一开始的？现在我看不到，我现在只能看到已完成和失败的。」
> 「你现在是在触达……但是你没有跟我说这个为啥失败了。触达向阳而生，就是我不清楚呀。」
> 「我现在进行到哪一步……你现在有，我觉得没问题。」（步骤流不动）

## 现状核实

`WorkerActivity` 只有 `current`（当前任务）+ `steps`（当前任务的步骤）+ `history`（跑过的），**没有 queued**，也没有今日总量；失败信息把 `error_code` 原样甩出来（`executor_lost` 这种机器码）。

## 改什么

1. **今日安排区块**（`components/WorkerDayPlan.tsx`）：共排 N / 已完成 M / 待跑 K / 要处理 J + 分段进度条 + 各业务线额度（6/55 单 · 还能加 49），下面是**按部门分组的待办清单**（这是此前完全没有的）。
2. **失败码人话化**（`api/error-codes.ts`）：一句结论（「机器失联」）+ 一句下一步（怎么办）+ 是否「要人处理」角标；机器码降级为灰色小字保留，供排查用。
3. 数据复用排程契约 `schedule.api`（一套契约两个视角），后端接入只改 `fetchSchedule` 一处。
