# Bug PrepPRD：Agent 自升级后断链 / 启动器僵尸打架（24h 内 3 次生产停机）

## 症状
Agent 核心自升级或版本清理后，客户机上的监听静默死亡数小时，无告警。用户体感 = "客服不回了"。24 小时内在 xian-rog 复现 3 次、XIAN-PC 1 次（5 个计划任务多实例乱象）。

## 根因（4 个，全部有日志/进程实锤）
1. **升级交接断链**：core-upgrader 写完 `.active-core` 指针后"优雅退出等启动器拉起新核心"，但启动器可能根本不存在（agent 被计划任务/调试方式直接启动，没有外层循环）→ 退出即停机（07-04 08:46→12:00 实录）。
2. **计划任务指死版本目录**：`/tr ...\v2.0.69\start.vbs`，自升级删旧目录后任务指向尸体，开机自启永久失效（v2.0.37、v2.0.69 两次实录）。
3. **僵尸启动循环**：旧版本 start.bat 的重试循环进程不死（v2.0.52、v2.0.69 各一次，07-04 同时 3 个），不停重生旧版 agent，和新实例互相"已有实例"集体秒退。
4. **agent.lock 陈旧 PID 误判**：锁只存 PID，不验证该 PID 是不是 zenithjoy-agent.exe；agent 全灭后 PID 被系统复用给别的进程 → 所有新实例误判"已在运行"秒退（07-03/07-04 各一次实录）。

## 修法（`services/agent/` 核心，一个 PR）

### 第 0 条（用户定的启动纪律，最重要）：启动第零阶段 = 环境收敛
Agent 进程启动后，**在连中台、下载任何东西、拉任何模块之前**，先做一轮幂等的环境收敛：
1. **清场**：杀掉本机所有旧版本启动循环（start.bat 僵尸）、重复 agent 实例（锁用 PID+进程名双验证，陈旧锁直接覆盖）
2. **修自启**：检查计划任务 `/tr` 指向——不是固定入口/指向已删目录 → 当场改正
3. **验配置**：.env / config.json / license 完整性检查，缺失或乱码 → 心跳上报具体缺什么（不是静默 dryrun）
4. **全部收敛完**，才进入：连中台 → 心跳 → 模块下载 → 自升级

### 其余修法
1. **锁活性校验**：agent.lock 存 PID + 进程名/exe 路径；PID 存活**且**进程名匹配才算"已在运行"，否则视为陈旧锁覆盖。
2. **升级交接闭环（先立后破）**：新核心先被拉起、完成它自己的环境收敛、心跳确认健康，旧核心才退出；拉起失败 → 不退出、回滚 `.active-core` 指针。
3. **启动器版本自检**：start.bat 循环每轮读 `.active-core`，发现自己不是活跃版本 → 立即退出循环（根治僵尸重生）。
4. **计划任务固定入口**：安装/升级时把任务 `/tr` 改指固定路径 launcher（升级 carry-over），不再指版本目录。

## Regression Test 计划（CI，永久）
- 锁判定纯函数单测：陈旧 PID（进程不存在 / 存在但名字不符）→ 判"可启动"；同名活进程 → 判"已运行"。
- 启动器版本自检逻辑单测：`.active-core` ≠ 自身版本 → 退出码非零。
- upgrader 交接单测：mock spawn 失败 → 不退出 + 指针回滚。
- 环境收敛幂等性单测：脏输入（僵尸清单/坏任务指向/缺配置）→ 输出收敛动作列表；干净输入 → 空动作。

## Proven-to-fire 守卫（环境接缝，CI 测不到，按哨兵死规矩）
- **Agent 开机自检**：检测同机重复 agent 实例 / 残留旧版启动循环 → 杀多余 + 心跳上报 `duplicate_instances`；部署后在 rog 故意起两个实例，亲眼看它报红杀掉。
- **中台心跳缺口告警**：agent 心跳断 >10 分钟 → dashboard 机器状态标红（07-04 早断 3.5 小时无人知晓）。
