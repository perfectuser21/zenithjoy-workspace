# 批量混剪 Golden Path v2

提案人：Cecelia（AI）。归属 Line05「视频剪辑」，journey_id `bb4f2154-d5d3-4836-af11-aeeaa3c2e8c8`。
一句话：客户已有一批（≥10段）自有素材时，系统自动批量组合出上百份候选短视频方案，客户挑中后导出通过内容安全自查的 1080P 高清成片。

本版基于 v1 + 三镜头(tech/product/risk) GAN 对抗 Round1 反馈（`.harness/feedback-r1.md`，verdict=REVISION，P0=0，P1=F1-F6）修订。v1 骨干判断（四步、三道 Gate、J1-J9 判定点、A1-A5 断言）本版不推翻，只逐条核销 F1-F6：补齐「切刀记录表」、外部依赖故障的客户可见/恢复路径、灰度阶段契约声明、A4 口径统一、候选级去重判定点、内容安全事故 SOP。逐条处理记录见文末「## 对抗核销记录」。

## Gate 0 · 技术可行性探索（开工第一个任务，先于任何功能代码）

**问题**：S2/S3/S4 的核心壁垒——语义检索匹配引擎（向量库选型/embedding 模型）、候选生成算法、Seedance/Happy Horse 补拍、阿里云超分、CosyVoice 声音克隆——**全库零调用点**（`explore-report.md` §S2/§S3/§S4 各行），成本、延迟、可用性均未验证。

- 探索项：①embedding 检索候选生成在客户级素材规模（≥10 段起步）下的延迟与成本是否可接受；②Seedance/Happy Horse/阿里云超分/CosyVoice 四个第三方 API 的账号/额度/SLA 是否可开通并达到可用响应时间。
- 结论三选一：**A** = 全部可行 → 按现有骨干继续；**B** = 部分不可行（例如补拍 API 不可用）→ 降级方案（S2 槶位缺素材分支改为"直接跳过该候选"，去掉 AI 补拍），回主理人重新拍板缩水后的 scope；**C** = 语义检索本身不可行（成本/延迟不可接受）→ 暂停，本 GP 需重新设计核心机制，不得强行上线。
- 预授权规则：结论 A/B 按对应方案继续；结论 C 暂停并升级主理人。
- **预算隔离（v2 新增，核销 P2）**：Gate 0 探索本身要真实调用四个第三方 API 试跑，从 `gp-contract-v2.json` 的 `budget_guard.gate0_exploration_reserved_usd` 单独划出预留额度，不与上线后运营预算混用。若 Gate 0 因预留额度耗尽而中断（不是因为延迟/成本本身判定不可接受），判定为**「预算不足需追加」**，回主理人申请追加预留额度重跑，**不得**直接下 Gate 0 结论 C（技术不可行）——避免把"钱没到位"误判成"技术不可行"。

## Gate 1 · 内容安全与声音克隆授权文书（碰对外发布 + 真实人物声音，S4）

- 客户授权协议模板必须含：①声音克隆对象是客户本人/员工/已获授权代言人的明确书面/电子确认，逐次勾选（非一次性总授权）；②内容安全自查未通过的素材/成片，客户授权系统转人工复核或删除的处置权；③对外发布责任划分（平台封号/法律追责归属，参照 Gate 2 资金门共用凭据管理规范）。
- 声音克隆功能首版**默认关闭**，客户逐次勾选授权后才开放该次生成；未过内容安全自查的成片**禁止导出**（fail-closed，见 A1/J7）。
- 无授权记录 = 功能入口不可点击，不是"生成后打免责水印"。
- **服务故障分支与鉴权分支不是同一件事（v2 新增，核销 F2）**：本 Gate 的 fail-closed 只管"未授权"——`consent!=true` 恒 403，不可绕过。"已授权但 CosyVoice 服务本身故障"（网络超时/服务不可用等真实故障）是另一个分支，语义是**降级为原声交付**而不是拒绝，客户可见处理方式见下文『外部依赖运行时故障』表④；这条分支失败**不阻断**成片主链路交付。

## Gate 2 · 第三方付费 API 预算门（S1/S2/S4 多处调用）

- 上线前必须完成：Gemini/Seedance/Happy Horse/阿里云超分/CosyVoice 各账号开通 + 额度预留 + 超时重试策略。团队已有真实付费调用先例可循（`content-judgment.ts` 调 Gemini、`video-remake.service.ts:369-373` 调 DashScope），但混剪需要的四个第三方能力**目前一个都没有接入代码**，凭据/额度从零搭建。
- `budget_guard` 生效：累计花费触达 `total_cost_cap_usd` 后续任务自动置为 `paused_budget`，人工确认前不再产生新调用，禁止静默继续扣费。
- **解除责任人明确（v2 新增，核销 P2）**：`paused_budget` 的人工确认责任人 = 主理人（本 GP 拍板人）。解除需主理人在 Brain 任务里显式批准继续，批准记录写入 `decisions` 表（六去向宪法②），不允许任何 AI 自行判断"看起来没问题"就解除。

## 切刀记录表（v2 新增，核销 F1）

按 `capability/references/step-cutting.md` §2/§3 方法，对骨干四步之间的 3 个相邻边界逐一跑 T1（可观察终态）/T2（失败可辨）/T3（可独立验收 EV）/T4（可停顿）四测。Gate 0/1/2 是横切的全局前置闸门与合规约束，不是流程时序上的候选片段，不参与本次边界扫刀。

| 相邻边界（片段A ｜ 片段B） | T1 可观察终态 | T2 失败可辨 | T3 独立 EV | T4 可停顿 | 结论 | 理由（一句话） |
|---|---|---|---|---|---|---|
| S1 素材可用库 ｜ S2 套路模板 | ✔ | ✔ | ✔ | ✔ | 切 | S1 终态="素材已识别/处理失败/人工复核中"可见；S2 终态="槶位分配结果"可见，两者是不同的客户可见状态，S1 坏了=素材没进库，S2 坏了=模板选不出/槶位分不出，是不同的失败；槶位分配结果本身可直接对客户可见数据写断言验收，不需要等到候选生成；客户选完素材可以隔几天再回来选模板 |
| S2 套路模板 ｜ S3 候选方案 | ✔ | ✔ | ✔ | ✔ | 切 | S2 终态="槶位分配结果确认"；S3 终态="50-300 条候选缩略图可选"，终态不同；S2 坏了=模板/补拍分配不出，S3 坏了=候选生不出来/候选量失控，客户经历的是不同种失败；候选页数据（候选数量、缩略图存在性）可独立断言，不依赖导出结果；候选生成完客户可以隔几天再选/导出，不影响已生成的候选池 |
| S3 候选方案 ｜ S4 高清成片 | ✔ | ✔ | ✔ | ✔ | 切 | S3 终态="候选已选定"；S4 终态="可下载的 1080P 成片"，终态不同；S3 坏了=候选生成/质量问题，S4 坏了=内容安全/水印未过或渲染导出失败，失败种类不同（A1/A2 断言分别验证两类失败）；导出的成片文件本身可用 ffprobe 独立验收，不依赖后续步骤；客户选完候选可以隔几天再点导出 |

⇒ 3 刀，4 步，落在 doctrine §5「3-5 步」区间内，无需并入或拆分。

## 外部依赖运行时故障：客户可见与恢复路径（v2 新增，核销 F2）

以下四类是"第三方服务本身不可用/超时/报错"类故障，区别于判定点表里的"内容判断"类分支（J1/J2/J6/J7/J8 处理的是"判断结果是什么"，本表处理的是"服务本身打不通时客户怎么办"）。

| # | 步骤 | 外部依赖 | 客户怎么发现失败（具体状态/文案） | 客户能做什么恢复 |
|---|---|---|---|---|
| ① | S1 | AI 打标签（Gemini 视频理解）/ Embedding 生成 | 素材库页面该条素材状态显示三态之一：`已识别`/`处理失败`/`人工复核中`（复用 `gp-contract` `fr_summary.statements[0]` 已定义的三态，不新增状态词）；状态为 `处理失败` 时鼠标悬浮/点击展开显示具体原因（如"标签服务超时，已自动重试 N 次"） | 客户可点击该条素材的「重新处理」按钮手动重试；超过自动重试上限（实现期定值，P2 记账）仍失败自动转入 `人工复核中`，客户可在素材详情看到"预计处理时间"提示；该条素材失败**不阻塞**素材库里其他已成功素材进入 S2/S3，只是该条被排除在候选池外 |

## 验收断言（Final E2E，冻结后 AI 不可改）

- **A1** 内容安全自查未通过或水印自查未通过的成片，导出接口恒拒绝返回下载文件；psql 查询对应 `content_id` 的 `safety_check_status`/`watermark_check_status` 字段，只要非 `passed`，`contents` 表上该条记录的 `export_url`/`download_url` 必须为 NULL（fail-closed，不允许"先给文件后补检查"）。
- **A2** 导出的高清成片必须通过 `ffprobe` 验证：存在视频流（`ffprobe -v error -select_streams v -show_entries stream=codec_type` 输出含 `video`）+ 分辨率 ≥ 1920x1080 + 时长与所选候选方案时长误差 ≤ 1 秒。
- **A3** 声音克隆功能被调用时，API 必须先校验 `voice_clone_consent` 字段：未授权（`consent!=true`）请求恒返回 403 并落审计日志；已授权请求成功后 `voice_clone_consent_record` 表存在对应授权凭据行（psql 查询存在性 + 授权时间早于生成任务创建时间）。**（v2 澄清）**本断言只覆盖"未授权"分支的 403 拒绝；"已授权但服务故障"分支不在 A3 范围内，属降级路径，验收方式见上表④——客户仍能拿到原声成片下载，不判定为整体失败。
- **A4（v2 改为软断言/告警式，核销 F4）** 候选生成 API（如 `GET /api/mashup/candidates`）返回的候选列表长度期望落在 [50, 300] 区间；Final E2E 测试用例分别构造素材数量边界场景验证返回值：若单次超出区间，记录告警日志 + 计入观测指标（`candidate_count_out_of_range_total` 计数器），**不判定该测试用例为 fail、不阻断导出主流程**——口径对齐 `gp-contract-v2.json` `lifelines_and_nfr` 里候选量控制的 `best_effort` 分级（理由：体验/成本优化项，超限不产生安全/资金后果，非命门，见合同该条 `rationale`）。仅当连续 N 次（数值留待实现期按真实素材分布回填，P2 记账）超区间时才升级为需人工介入的告警工单。若实现期发现候选量失控本身会引发安全/资金后果，需先把该项在合同里升级为 `lifeline`，再把 A4 改回硬 pass/fail 断言——两处必须同步改，不能只改一处。
- **A5** 第三方付费 API（Seedance/Happy Horse/阿里云超分/CosyVoice/Gemini）累计调用花费达到 `budget_guard.total_cost_cap_usd` 后，新任务状态必须置为 `paused_budget`（psql 查询该状态行存在），且日志证明后续调用未真实发起（无对应 provider 的出站请求记录）。

## 事故 SOP：内容安全 Gate 失守（违规内容已被下载/发布出去）（v2 新增，核销 F6）

Gate1/J7/A1 拦的是"未来的下载请求"；本节是万一 Gate **已经**误判放行、违规成片已被客户下载甚至已发布到第三方平台之后的兜底动作，触发来源：灰度期人工抽样复核 / 客户投诉 / 第三方平台通知。

1. **下架（发现后 0-2 小时内）**
   - 立即执行 `rollback_triggers` 已定义的"立即下线导出入口熔断"，阻止同类内容继续被下载（复用 v1 已有动作，不重复发明）。
   - 若内容已发布到抖音/视频号等第三方平台：值班人员通过发布器已有的平台账号，调用平台侧已有的下架/删除 API（复用现有发布器凭据，不新建通道）主动下架；若发布渠道不在系统程序化下架范围内（客户自行转发/二次分发），书面通知客户要求自行下架，并记录客户响应状态。
2. **报备对象**
   - 内部：升级给主理人，报备内容含涉事客户 ID、内容 ID（`content_id`）、违规类型（内容安全/水印/未授权声音克隆）、发布渠道、时间线。
   - 涉及法律层面风险（未授权声音克隆、版权侵权）：同步升级给合规/法务对接人；本 SOP 只负责触发升级动作，不做责任判定。
3. **客户通知**
   - 24 小时内以书面形式（邮件/工单）通知涉事客户：说明发生了什么（内容安全自查误判放行）、已采取的下架动作、是否需要客户配合（如平台申诉/自行删除转发内容）、后续该客户账号的内容安全/声音克隆相关功能临时收紧为人工全量复核（代替自动 Gate），直至复核完成后恢复自动化。
4. **事后记账**
   - 本次事故计入判定点表 J7 的漏判记录；若灰度期内累计发生 1 次此类"侵权/违规内容被实际导出"的漏判事故，直接触发 `gp-contract` `shutdown_conditions` 已定义的下线条件，走既定下线流程——本 SOP 不另行发明新的独立阈值，只负责在事故发生的当下把动作做完、把人通知到。
