# 修复：M4 ADB 服务争抢与通道归属

任务：c9eff684-0f1a-48df-b694-9459216ee81e；调查：615e8419-0761-4f00-adbd-08182185d767。

GP-Anchor: none(infra)

主责为 Cecelia 基础设施部／系统看护／设备与手机台账。通道是获客、发布和微信共用的横切底座；本次不更改六层树。

## 已证实的问题

M4 的 5037、5041、5042 三个 ADB 服务扫描同一批 USB 手机，内核记录排他接口冲突；USB 重新枚举后设备归属端口漂移。5042 来自历史云机验收在 M4 的 start-server 命令。默认端口的恢复服务会误报其他服务接管的手机离线。

小彩的 USB 硬连接丢失是独立可用性问题，软件收敛不冒充修复线材、Hub 或手机端连接。

## 获授权的修复范围

- M4 实体 USB 使用一个受管 ADB 服务和宿主配置。MMV 云手机保留独立网络入口及当前密钥、租户和隔离状态。
- 普通业务统一通过受管客户端连接；不能自行启动或停止服务，也不能用环境端口绕过宿主配置。
- 获客、录音、账号巡查、手机墙、领单和恢复使用同一配置；旧手机墙自启入口纳入迁移。
- 集中巡检服务数量、宿主端点、设备归属和协议；只读检查不自动拉起 ADB。
- 持维护租约、核实际执行者和未知副作用后才迁移；精确核对主机、PID、用户和启动时间，不 killall，不跨宿主清理。

## 发布与迁移顺序

两阶段执行。先沿原正式 Source、Pilot、部署 admission 和 global guard 交付源码；此时不激活宿主策略、不停 ADB，普通业务保留尚未迁移的入口。原 controller/helper device barrier 不允许任何本地设备锁，不能为本人维护锁放宽它。代码正式部署并读回后，另以已部署的维护入口执行运维切换：先持中央维护保留和四台本地维护锁，暂停会自启的消费者，核对实际宿主、来源字节和进程身份，再切换服务和宿主策略。维护动作有独立计划、日志和状态读回；代码发布成功不等于 ADB 迁移成功。失败保留原件与维护状态，不伪写 ACK，也不把研究目录脚本热补为生产源码。

## 验收

- 永久 RED→GREEN 守卫覆盖额外服务、错误端口和配置缺失；请求只能为只读 smart socket。
- 所有现役消费者不再裸调用可自动启动服务的 ADB；MMV 云连接和原资源隔离保持可核验。
- 迁移拒绝活动或未知执行者、设备锁冲突、PID 变化和错误宿主。
- 正式检查和实际部署读回通过；能枚举的实体手机按序列号在唯一服务上可用。小彩未被 USB 枚举时明确报告离线。
- 不发送 104，不改变公司评分政策，不以空队列或客户端 exit0 代替业务验收。

## 发布范围分棒

获客底座、手机墙、领单器与恢复服务先由共同底座发布；账号巡查的 collector／预检与不可变 leaf、控制器及 schedule 绑定按其独立窄合同另发。本 PR 不修改巡查业务源码、辅助文件清单或旧验收指纹，不声称巡查已升级。现有检查器仍对各自发布的完整 diff 准入，不裁剪候选 diff、不扩大允许清单。巡查补丁与原验证证据保留，未升级入口须在实际切换时明确管理。
