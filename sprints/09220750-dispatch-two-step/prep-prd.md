# 小改动 PrepPRD：派活面板改成两步——先选活，选完才进入这件活的输入窗口

## 改什么

`apps/dashboard/src/components/DispatchJobDialog.tsx` 的交互结构。

**现状（单页展开式）**：设备下拉、部门下拉、活列表、输入框、时间窗口、派下去按钮
全部堆在同一个弹窗里从上往下排。点一件活之后，在**同一屏下方**展开它的字段。
逻辑上分了层，视觉上就是主理人说的「所有任务都挤到一起，都是一个面」。

**改成（两步式）**：

    第 1 步「派给谁、派什么」        第 2 步「<这件活的名字>」
    ┌────────────────────┐      ┌────────────────────┐
    │ 设备 [下拉]  部门 [下拉] │      │ ← 返回   派给 M4-小诺  │
    │                    │      │                    │
    │ 这个部门可以派的活：      │ 点一件 │ 关键词 [__________]  │
    │  · 按关键词采收线索  →   │ ───→ │ 最多采几条 [__]      │
    │  · 给指定的人发私信  →   │      │ 什么时候跑 [下拉]     │
    │  · 跑一轮触达      →   │      │        [取消] [派下去] │
    └────────────────────┘      └────────────────────┘

第 2 步**不再显示**设备与部门下拉（那正是"挤在一个面"的来源），改为一行只读上下文
「派给 <设备名> · <部门>」；要换设备就返回第 1 步。

## 为什么改

主理人原话：「所有的任务都挤到一起，都是一个面。你其实应该是让我选择，比如说我到底
是哪一种任务，**然后才进入它的输入窗口**。」

关键在"然后才进入"——要的是分步，不是同屏展开。

## 几个容易做错的边界（先定下来，逐条配测试）

| 情况 | 定的行为 | 为什么 |
|---|---|---|
| 返回第 1 步后，重新点**同一件**活 | 保留刚才填到一半的值 | 填了一半回去看一眼再回来，值没了会恼人 |
| 返回第 1 步后，点**另一件**活 | 清空，用新活的默认值 | 绝不能把上一件活的输入带进另一件 |
| 换部门 | 回到第 1 步，已选的活与值一并清掉 | 现有行为，保持 |
| 后端拒绝（窗口太窄/额度不够） | **停在第 2 步**显示原因 | 跳回第 1 步等于让人重填一遍 |
| 提交中 | 返回与取消一并禁用 | 半途返回会让"派下去"落在不确定的状态上 |
| 这个部门没活 | 停在第 1 步，明说没有 | 现有行为，保持 |
| 一台设备都没有 | 第 1 步就说清楚，不给进第 2 步 | 现有行为，保持 |

## 影响范围

只动 `DispatchJobDialog.tsx` 与它的测试。`job-catalog.ts`（部门→活→字段的数据）
与 `dispatchJob` API 都不动——数据分层本来就是对的，错的只是渲染成了一个面。

`WorkersPage.tsx` 的入口按钮（「派活」）不动。

## 验收标准

- [ ] 第 1 步看不到任何输入框（当场能证明"不是一个面"）
- [ ] 点一件活才进入第 2 步，且只显示这件活的字段
- [ ] 第 2 步能返回，返回后重选同一件活保留值、换一件活清空
- [ ] 后端拒绝时停在第 2 步
- [ ] 提交中返回按钮禁用
- [ ] 窗口语义说明在第 2 步仍在
- [ ] 原有 21 条测试该保留的行为全部不回退
- [ ] CI 全绿
