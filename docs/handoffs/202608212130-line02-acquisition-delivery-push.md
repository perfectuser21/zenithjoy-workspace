## 一、今天最重要的一个认知纠正

**「当时全部跑通了」的真实含义是「那一次每一步各成功了一次」，不是「这条链能工作」。**

判定链转写率按天（全部历史）：

```
07-18   0%      07-28   13%
07-19   8%      07-29    7%
07-20   0%      08-17    0%
07-21  43%      08-18   11%
07-22   0%      08-19   17%   ← 曾被记为「端到端首次全通」那天
07-24 100%      08-20   71%   ← 修复当天
```

**从 7 月 18 日起一个月来就没好过。** 0819 那个「首次全通」里程碑是真的，稳定是假的
（那天转写 17%、私信 4 成 5 败）。

之所以没人发现，两个机制原因（今天都已堵上）：
1. **守卫太弱** —— gp2 smoke 那条「真调 DeepSeek 判定」只发 **1 条评论**，
   而分档的断裂点在 6 条 → 判定链整个坏掉它也照样绿
2. **失败原因不落地** —— 私信正表里只有 `failed` 三个字，错误码被丢在
   `publish_tasks.response` 的 JSONB 里，四次修复都在盲修

## 四、⚠️ 下一个赛程第一件事：每小时频控卡住了重投

#1693 上线后立刻验证：一次 build 从 `assigned=8, skipped_dedup=85` 变成
`assigned=35, skipped_dedup=0` —— 85 条被白挡的重投机会全回来了。

**但 35 条里 33 条当场变成 `limited`，只有 2 条进队列、还被排到了 8 月 28-29 号。**

```
limited   126 条
queued      2 条   排程 08-28 15:21 ~ 08-29 15:14
```

日配额远没用满（`人工智能小诺考评 9/30`、`绿野动漫屋 7/30`、`秦军餐饮 5/30`、`嘻嘻 5/30`），
**所以撞的是「每小时 5 条」那道闸**（`dm_per_hour=5`）。

**这意味着重投的收益目前被频控吃掉了。** 下一步要判断：
- `dm_per_hour=5` 是抖音风控的真实红线，还是我们自己拍的保守值？
- 如果是自己拍的，把它调到 10 就能把重投的收益释放出来（日配额撑得住）
- 排程被推到一周后也需要看：`buildAssignments` 的排期算法在候选多于配额时
  是不是应该丢弃而不是排到一周后（排一周后等于没派）

**这是目前离交付最近的一个杠杆，比继续修 RPA 划算得多。**

## 六、今天踩的坑（下一个赛程别再踩）

**方法论上的（最贵的）**：我三次拿少量样本当规律就动手改——
①据「同源」把采集的成因外推到私信（白改三轮）②一条失败现场当 40% 的普遍成因
③闪屏假设装机后 `TARGET_ABSENT` 依旧。**唯一真正起作用的是 #1689「让失败自带现场」**——
它没修任何 bug，但让每次犯错都在一轮内被数据拆穿。规矩已进 invariant 表（`93ed0761`）
+ CI 闸 `lint-rpa-failure-scene`，CLAUDE.md 只留指针。

**操作上的**：
- `git checkout --` 会冲掉未提交的实现 —— **变异测试前必须先提交**（今天犯了两次）
- 探针脚本别层层字符串派生（继承了上一层只有 25 条的评论池，得出假结论）
- **重装 APK 必丢截屏授权**（MediaProjection 是会话级）—— 每次升级都要重点一次
- 荣耀装未上架 APK 有**四层闸**，第四层「允许本次安装」是句子里的**蓝色 ClickableSpan**，
  `uiautomator dump` 看不见，只能截图量坐标；**别盲点坐标**（我点进过应用市场）
- `psq` 的 `INSERT..RETURNING` 输出**两行**（值 + `INSERT 0 1`），要先 `head -1`
- 改 `.github/workflows/**` 的 PR **标题必须带 `[CONFIG]`**，且**改标题不刷新 event payload**，
  要重新 push（与 `lint-gp-anchor` 同坑）
- `sprints/*/tests/` 是**冻结的合同测试**，改了必被 `lint-contract-test-immutability` 拦；
  正解是让生产代码兼容它，不是改它
- `Smoke Glob Runner` 有真 flaky（不同 PR 挂在不同脚本上），main 同期是绿的，重跑即过
