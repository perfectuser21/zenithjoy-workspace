1. **PR #1501**：`<script type="module">` 打包产物直接以 `file://` 加载被 Chromium 模块 CORS 限制静默拦截（不触发任何 JS 错误，`NavigationCompleted` 照常报成功，`#root` 永远空）。改用 `SetVirtualHostNameToFolderMapping`。
2. **PR #1506**：切到虚拟host后用了 `https://`，导致混合内容拦截——页面无法 fetch/EventSource 连本地 `http://localhost:58432` 后端。改用 `http://` 虚拟host（本地环回不需要传输层加密）。
3. **PR #1506**：`panel-events-route.ts`/`wechat-rpa.ts` 的路由自己接管了 `request` 监听器，从未设置 `Access-Control-Allow-Origin`——网页现在跑在虚拟host，与 Agent 本地服务器跨源，浏览器静默拦截。
4. **PR #1506**：`snapshotLines()` 从未带 `connected` 字段——`CollapsedStrip.tsx` 用 `lines.filter(l=>l.connected)` 决定上不上灯，字段缺失时恒为 `undefined`/falsy，即使前三个 bug 全修完，收起态灯带依然永远空白。
5. **PR #1506**：原生宿主热键(Ctrl+Alt+Z)/托盘点击只调用 `ApplyWindowMode` 改窗口几何尺寸，从未通知网页内部的 `expanded` state——按热键后窗口确实变全屏，但内容仍渲染收起态那个 6px 小灯，客户看到几乎全白的全屏窗口。新增 `native-bridge.ts` 的 `onHostExpandChanged` + C# 侧 `NotifyWebExpandChanged` 双向打通。

## 排查手法（沉淀下来，后续同类真机验证可复用）

- **`PrintWindow` + `PW_RENDERFULLCONTENT`** 截图看 WebView2 真实渲染内容——普通 `CopyFromScreen`/BitBlt 截不到 WebView2 的 GPU 合成内容，会显示纯白，误判"没渲染"。
- **`window.chrome.webview.postMessage` 诊断链路**——`ExecuteScriptAsync` **不会自动 await 脚本里返回的 Promise**，`JSON.stringify(pendingPromise)` 会 serialize 出 `"{}"`（Promise 对象无自有可枚举属性），一度误判"网络不通"。改用脚本内部自己 `await` 完再 `postMessage` 回传，C# 侧监听 `WebMessageReceived` 才拿到真实诊断数据。
- **`schtasks /Create ... /IT` 把 exe 跑进 Session 1 交互桌面**——直接 `ssh exec` 跑在非交互 Session，WebView2 创建 `CoreWebView2Controller` 会报 `COMException 0x80070578`（无效窗口句柄）。`PsExec -i 1` 在此环境遭遇 access denied（原因未查明，疑似 SSH 会话 token 权限不足），改用 Windows 任务计划程序的 `/IT`（交互式登录，S4U logon）绕过。
- **真实鼠标点击验证 WS_EX_TRANSPARENT**：自建一个 WinForms Form（避免依赖外部 app 异步启动时序，如新版 WinUI3 Notepad），定位到与面板 RpaMini 矩形重叠，用 `mouse_event` 合成点击，检查点击是否命中背后窗口（`form.Click` 事件触发 + `GetForegroundWindow()` 变成背后窗口）而非面板本身。
- **端口冲突排查**：xian-rog 是共享的 self-hosted CI 真机，已有真实生产 `zenithjoy-agent.exe`（`127.0.0.1:58432`）常驻。自己的测试 harness 若也监听 58432（`0.0.0.0`/`[::]` 通配符绑定）会与已有进程"共存"但路由到不同进程，导致诡异的部分连通/部分404。用 `netstat -ano` + `wmic process where ProcessId=X get CommandLine` 才查清真相——换独立端口（58433）测试即可，不碰共享的生产进程。
