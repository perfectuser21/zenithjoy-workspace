## 完成
- 2026-07-28 Path2安卓5台真机复测暴露3处服务端零留痕缺口，根因均已查明并修复：
  1. `agent-burner.ts` `/account-scan-result`：手机内部自动循环扫描失败（`request_id` 形如 `scan-<timestamp>` 非UUID，占真机常态运行绝大多数场景）此前被无条件跳过持久化，`error_code`/`screenshot_b64`/`tree_dump` 只留在手机本地logcat。改为 `ok!==true` 时无条件落库到新表 `agent_scan_failures`（migration `20260728_134234_agent_scan_failures.sql`）
  2. `customer-admin.ts` 绑定失败分支（成员已绑/PC已绑/配额满/唯一约束冲突）此前只回4xx不写库。补 `audit()` 调用，复用既有 `customer_admin_audit` 表
  3. `scheduler.ts`：`/collect/sweep-timeouts` 看门狗端点（10分钟超时把 running/stage_1_done 转终态+写 error_code=COLLECT_TIMEOUT）代码早就写好但从未被任何调度器调用，等于摆设。抽成 `acquisition.ts` 导出函数 `sweepCollectTimeouts`，`scheduler.ts` 每分钟tick调用（同 `dm-dispatch-sweep` 既有模式，含再入守卫）
- golden-path-2-smoke.sh 新增 Step 30（account-scan-result 失败留痕 HTTP 断言）；sweep-timeouts接线与绑定审计由新增 vitest 回归覆盖（`services/scheduler.test.ts` / `customer-admin.test.ts` / `agent-burner.test.ts`）
- apps/api 全量 vitest 233文件/1869用例通过，PR #1490 CI全绿并已 squash merge
- 同一会话前置工作：救援合并了搁置6天的 PR #1456（Android信号上报能力），过程中额外发现并修复两个真实生产bug（error_code白名单命名冲突、FR-3 latest_reply被同请求内rescoreLead覆盖），详见 decision `004c1d6c`
