## 一、三层真根因

### ① 无障碍授权落在 `.e2e` 变体包上，干活的 prod 包一条都没有 ← 小白干不了活的直接原因

```
Enabled services:{ com.zenithjoy.agent.e2e/...DouyinCollectService,
                   com.zenithjoy.agent.e2e/...DouyinDmOutreachService,
                   com.zenithjoy.agent.e2e/...DeviceAccountScanService }

真正在跑/拉任务/心跳的进程: com.zenithjoy.agent      (prod 2.1.28, pid 7205)  → 连 staging
另一个也在跑:              com.zenithjoy.agent.e2e   (2.1.24-e2e, pid 10809) → 连 prod
```

prod 包的 `DouyinCollectService` 未绑定 → 派发广播进虚空 → 实录到每 30 秒重试一次、永不 ack。

旧自检 `collectServiceEnabled()` 比的是 `Settings.Secure` 字符串里有没有 `DouyinCollectService`
—— 字符串里确实有，只是包名前缀是 `.e2e`。**既不看包名，也不看 Bound**。
这是上一份交接单第六节「自检显示无障碍✅已开启在撒谎」的**完整版**：不只是 Enabled≠Bound，
**连包名都不看**。

`AgentService.REQUIRED_ACCESSIBILITY_SERVICES` 更糟：硬编码 prod 包名 + 用短格式
`pkg/.collect.Xxx` 与真机的全限定格式 `pkg/com.zenithjoy.agent.collect.Xxx` 做精确字符串比较
→ **恒报缺失（恒假红）**，长期被当噪音无视。已删除。

### ② 队列僵尸死锁（结构性，全机队都会中，只是没碰上）

`CollectTaskQueue.currentJob` 只有 4 条清除路径、全部依赖 `DouyinCollectService` 回调；
而 `startDispatchAckWatchdog` 在 `currentAccepted == true` 之后**主动放弃**
（`if (... || currentAccepted) return@launch`）。

于是「接了但没跑完」（服务被 ROM 杀、抖音拉不起走了无回调的错误分支）落进**完全没人管的真空区**：
currentJob 永久挂着，`processNextQueuedTask()` 第一行 `if (currentJob != null) return`
把此后所有任务挡在门外，**只入队不派发、全程零日志**。

中台侧看到的形状：任务被拉走标 running → 10 分钟后被 `sweep-timeouts` 收成 failed → videos=0。
小白 0819 当天 12 个任务全是这个形状。**强杀进程重启立刻恢复** —— 这就是「时好时坏」的另一半真凶。

### ③ okhttp debug 刷屏 —— 让前两层查不出来的元凶

两台真机（小白 ColorOS / 小黄 MagicOS）的 `getprop` 都有 **`persist.log.tag=V`**，
okhttp 4.12 内部每条日志前的 `logger.isLoggable(Level.FINE)` 因此恒真。
实测按 pid 抓小白 agent 日志：**302 行里 286 行是 okhttp 噪音（95%）**，
agent 自己的日志活不过 1 分钟就被冲出 logcat 环形缓冲区。

上一份交接单那句「只有 WebSocket 活动」不是"只有 WS 在动"，是**别的全被挤掉了**；
「没有 `agent started` 这行」也是同一个原因 —— 它开机时打过，早被冲走。

**绕开它的办法**（本次实际用的）：`adb logcat -c` 清空后起**流式**抓取写文件，
再投任务，而不是事后 `logcat -d` 捞历史。

## 四、给下一个大脑的操作要点

- **四台真机连的是 staging 不是 prod**：查库要 `docker exec zenithjoy-db-postgres psql -U zenithjoy -d zenithjoy_staging`（prod 库里那几行 2.1.24-e2e 是 e2e 包的）。
- **小白 = `ssh xian-m4` → `adb -s 192.168.3.242:5555`**，小黄 = `192.168.3.236:5555`。
- **判无障碍真假只看包名前缀**：`adb shell dumpsys accessibility | grep 'Enabled services'`。
- **`pending-collect-tasks` 有副作用**（拉取即标 running）：诊断时**绝不要手动 curl 它**，
  会替设备把任务拉走、把现场污染成"设备没轮询"。本次改用「直接往表里 INSERT 一个 pending 任务，
  然后只读状态」这种零副作用探针。
- **抓真机日志用流式不用 `-d`**：`adb logcat -c` 后 `nohup adb logcat -v time --pid=<pid> > /tmp/x.log &`，
  再触发行为。事后捞历史必然被噪音冲掉（2.1.29 之后这条会缓解，但流式仍然更可靠）。
