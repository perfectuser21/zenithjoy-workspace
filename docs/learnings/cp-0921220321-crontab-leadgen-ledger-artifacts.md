## 基座1/7：crontab 获客流水线补账本+阶段工件+续跑（2026-09-22）

PR #1937 · task b4b09cdd · 决策 adf7d620（不需要 n8n）/ 01d0af0a（路径 B）

### 根本原因（这次学到的）
1. **逐 task 两段审查全过，整分支终审"真跑脚本"仍抓出 3 处接线缺陷**：`eval` 出来的变量没 `export` 就调子进程（账本 attempt 永远 null）、计数判据 `0>=0` 在目录不可写时假绿、把过滤后的词单传给下游撞了合同哈希。读 diff 推断看不出跨进程/跨文件的接线问题，只有把脚本跑起来才能看见。
2. **计划本身携带 5 处缺陷**（finalize 自检恒真、`set -u` 打破"永远 exit 0"、metrics 不拒自造键、hash_mismatch 用 n=1 覆盖已完成词、正常退让也 escalate）。"计划里含完整代码"只保证实现者不会走偏，不保证代码对；reviewer 对计划代码要和对实现一样挑。
3. **与 main 并行时同一个 CI step 被两边各加一份**（装 zsh）。rebase 时取上游、丢自己那份。改 CI 之前先 `fetch` 看 main。
4. **规格层定义决定了功能的真实边界**：`run_id` 含 TAG（每晚不同）→ cron 场景下续跑永不触发，只对同 TAG 手工重跑有效。handoff 里必须如实写，不能宣称"续跑已上产"。
