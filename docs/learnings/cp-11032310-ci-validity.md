## CI 绿灯必须来自有效证据（2026-11-03）

### 根本原因

安全审计将错误 JSON 当成空漏洞集；多个聚合仅检查一个布尔路由而忽略路由本身失败；登记检查只 grep 路径；投影检查在验证前重新生成被验物。页面测试内复制逻辑、核心门禁只检查语法，都会出现实现已坏而测试仍绿的情况。

### 下次预防

- 校验上游状态、证据完整性和输出类型后，再判断是否选中下游。
- 明确失败、取消、不确定和未评估的区别；实际任务失败不得因 false 路由而消失。
- 对事件 SHA 和 Git 差异失败关闭，用完整依赖输入推导消费者。
- 对真实脚本/模块注入失败，保留正常正例并确认故障能击穿业务断言。
- 登记只证明库存存在，执行由真实 workflow/job/command 证明。
- 生成与验证分离；CI 不能悄悄修平提交中的漂移。
- 校验真实输入/输出形状与消费者：数组和 Playwright storageState、Secret 名称、通知 URL 都属于同一链路合同。
