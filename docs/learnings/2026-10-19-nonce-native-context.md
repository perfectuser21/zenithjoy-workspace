# 临时输入框的复制清空也必须保持界面上下文

小蓝正式037e的102在录音前核验视频身份时失败。typed原件有抖音唯一且聚焦的精确nonce，empty原件却是Honor添加搜索小组件确认框。只能证明界面在复制清空链期间外逃，不能从两帧推断具体触发键。原nonce拒绝是正确保护，不能通过放宽空框或预期视频ID消除失败。

新实现复用现有原生长按、COPY、MOVE_END和确切长度删除；长按和COPY后分别取新证据，确认前台和原字段仍然是完整nonce。出现系统界面时停止后续按键，保留empty后追加粘贴完整nonce及返回原详情验证。既有SDK31输入法适配保持独立，不伪造SDK选分支。

新增controller回归先在旧实现3失败/5通过：两种界面外逃都仍会继续按键，成功路径也保留复制阶段组合键。修复后新8例与既有SDK/占位文本/锁回归合计107通过，零跳过。现场真实恢复仍须正式发布后的独占Honor验收。

同次Skill接手只保留RPC_OPERATION_FAILED，原底层cause未记录，不能断言是网络。独立源码及现场证据证明此次未到官方child派发，已按原owner收尾并独验归位，随后精确释放两层锁；视频隔离和失败原件保留。

PR2221首次正式全控制器回归暴露10项连续身份失败：原模拟设备没有实现暂存框内同点650ms长按选择，导致COPY仍读到旧短链；同时新复制函数给原非SDK31无owner入口增加了原合同没有的前置。不得给全部测试硬塞owner来隐藏兼容回归。先保官方2793通过/10失败日志，再补真实长按模型（仅暂存框精确同点650ms）和永久无owner/错owner负例。生产仅恢复SDK31或显式owner才验锁的既有权限，target、阶段新鲜字段、前台及完整nonce后验均保留。无owner入口不能声称已证明持锁。
