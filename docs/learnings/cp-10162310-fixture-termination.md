## 录制负例模拟器退出窗口导致错误身份判定（2026-10-16）

### 根本原因

正式发布回归在 Node 22 中出现 wrong_path 负例失败。真实只读进程原件证明：模拟 zsh 收到停止信号后立即 exit，在同 UID、PPID 和启动时间的退出窗口中，argv 短暂变成 `(zsh)`，尚未进入僵尸态；生产控制器严格核完整 argv，正确拒绝继续处置。测试却把 trap 写出的停止标记误当真实退出。

### 下次预防

- [x] 负例必须独立读回真实进程已消失或为僵尸态，收到信号不等于停止。
- [x] 只有明确启用且拥有正常身份的受控负例忽略 INT/TERM 退出，让生产控制器执行原有逐次身份确认及 KILL；外来/未知身份保持原清理行为。
- [x] 保留原 reason/status/停止/所有权断言、300 秒预算、4 并发及无 HOME 尾组；不得放宽生产身份门禁来通过测试。
- [x] 同一 Node 主版本和发布环境白名单中执行独立 4 并发验证；macOS 证据不冒充 Linux 官方 Pilot 验收。

本次仅修测试模拟器。旧正式 Pilot 只有 stdout 摘要、没有正文，无法证明旧官方失败也是此具体断言；本地同环境诊断确实复现并完成原件取证。
