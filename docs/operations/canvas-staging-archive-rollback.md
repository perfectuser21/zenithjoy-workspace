# 画布 staging 的归档回滚

本机制仅用于已经留有健康验收 `receipt.json` 的历史画布镜像；不归档、不删除任何数据卷或客户文件。原镜像仍在时回滚保持原有流程。归档与镜像删除属于另一次运维操作，不因本代码合并而自动发生。

## 归档格式和校验

将该版本 `docker image save` 的完整 OCI tar 存放在 `/opt/zenithjoy-backups/canvas-archives/<完整提交 SHA>/image.archive.tar`。同一目录的 `image.archive.json` 由执行归档的运维人员生成：

```json
{"version":1,"sha256":"<tar 的 SHA-256 小写十六进制>","image_id":"sha256:<原 receipt 的镜像 ID>","required_free_bytes":4000000000}
```

数字仅作格式示例。`required_free_bytes` 必须使用目标环境实际测得的完整镜像加载峰值，并覆盖所有独有层及加载临时空间；不可直接套用示例。回滚入口在此基础上再保留 512 MiB 系统空间。tar、manifest、receipt 均须为执行用户所有的非符号链接普通文件，权限不允许 group 或 other 访问；归档目录应为 root 独占目录。

入口只接受本机 Docker 的已知存储布局，确认 `/var/lib/docker` 和 `/var/lib/containerd` 在同一文件系统，按 containerd 文件系统的实际可用空间检查。它验证受保护目录链、归档 SHA-256、receipt 镜像 ID、OCI index 和 blob 摘要，以及 Docker manifest 仅包含目标标签，再执行 `docker load` 并再次核对镜像 ID。空间计算同时考虑压缩内容、最大 blob 的临时副本和展开层并增加余量，取这个估算与人工测得峰值的较大者。未知存储布局、校验或加载失败时停止，不运行 Compose，不拉取其他镜像。

## 移除本地镜像前

1. 固定要归档的版本、镜像 ID、容器及卷引用；通过验收的 receipt 和版本源码保留在原目录。确认归档不包含凭据，如有凭据必须使用经批准的安全存储和恢复方法。
2. 先在独立存储完成归档，校验来源与目标摘要；在独立 Docker 数据目录真正导入，核对 ID，并测量峰值空间。记录原容器配置、挂载和恢复步骤；保留客户数据库与卷。
3. 确认包含本恢复能力的回滚入口已合并并部署到实际 CI 执行路径；验证归档可在目标主机获取，且空间满足读取和恢复。核对其他调用方不会依赖被移除的停止容器。
4. 只有上述检查全部通过，才能按获授权的清理范围移除指定停用容器及镜像。发生问题时先恢复归档并确认 ID，再执行原回滚流程。

归档副本丢失、空间不足、CI 入口尚未更新或尚未完成独立恢复验证时，不得删除原回滚镜像。
