# Path 2 安卓智能获客 Golden Path 员工验收 SOP 设计

**日期：** 2026-07-27  
**适用版本：** Android `2.1.16`（versionCode `20`）  
**后端基线：** Production / Staging 均为 Git SHA `5c78a2ed`  
**验收环境：** Staging 真实闭环；Production 只读冒烟  
**MAP：** Path 2「客户智能获客」

## 1. 目标

交付一份员工可以逐项执行、逐项留证、逐项打标的安卓真机验收 SOP，用真实证据回答三个问题：

1. 安卓 Agent 是否能看见正确的抖音页面、视频、评论者和目标账号，即“眼”是否正常。
2. 安卓 Agent 是否能完成点击、返回、输入、发送并取得真实回执，即“手”是否正常。
3. Path 2 MAP 的每一段是否达到可交付标准；未实现能力不得由员工手工补动作后标为通过。

SOP 不以“页面看起来正常”“后台生成了任务”或“点击过发送按钮”作为通过依据。

## 2. 已确认的当前版本事实

### 2.1 版本与环境

- Production 与 Staging 的智能获客后端源码 SHA 相同，差异为 0 个 commit。
- 两套环境使用同一个 Android APK。
- 两套运行数据完全隔离：
  - Production：`wss://autopilot.zenjoymedia.media/agent-ws`
  - Staging：`wss://staging-autopilot.zenjoymedia.media/agent-ws`
- APK 手工首次配置的默认地址是 Production。员工必须以 App 状态页的 API 地址为准，不能根据 APK 文件或网页地址猜测环境。

### 2.2 当前自动与人工验收边界

- 现有真机 smoke 已覆盖：
  - Android 设备与 Agent 自检；
  - 派发采集任务；
  - 任务进入终态；
  - 至少 2 个真实视频 ID；
  - 至少 1 个视频完成内容判定；
  - 有匹配视频时产生真实 Lead；
  - Lead 语义质量与 `profile_url` 完整性；
  - 创建私信派单。
- 自动 smoke 只证明“私信单已创建”，不能证明手机完成真实私信。
- Android APK 中存在真实私信执行链：精确搜索抖音号、校验目标主页、关注/点赞热身、进入私信、完整输入、发送、读取回执。
- Android APK 中没有“自动公开回评”的执行入口。员工手工回评只能记为人工 workaround，不能记为产品通过。

因此，本版本可以单独验收“Android 私信子链”，但完整 Path 2 MAP 因公开回评缺失不能获得总 `PASS`。

## 3. 采用的文档方案

采用“双层验收包”：

### 3.1 第一层：员工执行版

面向不需要阅读代码和数据库的测试员工。每个检查点固定包含：

- 测试目的；
- 操作步骤；
- 手机应发生的可见行为；
- 后台或收件端应出现的结果；
- 必须保存的证据；
- `PASS / FAIL / BLOCKED / NOT IMPLEMENTED` 判定。

### 3.2 第二层：主管审计版

面向测试负责人或研发值班人员，包含：

- FR、NFR、Invariant 对照表；
- 任务 ID、Agent ID、Lead ID 的串联检查；
- API/数据库抽查点；
- 缺陷严重级别；
- 最终验收结论模板。

员工执行层不得依赖 adb、SSH 或 psql。需要后台数据证明的项目由主管审计层完成，且必须与员工提交的同一个任务 ID 对上。

## 4. SOP 结构

正式 SOP 按以下顺序组织。

### 4.1 验收单首页

记录：

- 测试日期、测试人、复核人；
- 手机品牌、型号、Android 版本；
- 抖音版本；
- Agent 版本；
- Agent ID、Machine ID；
- API 地址；
- Staging 测试租户；
- 采集任务 ID；
- 受控发送账号与受控收件账号；
- 测试关键词、对标视频 URL、唯一水印话术。

唯一水印话术格式：

`【ZJ-STG-YYYYMMDD-HHMM-员工缩写】这是一条智能获客验收消息，请勿回复。`

每轮只能使用一个新的水印，禁止重复使用旧消息截图充当证据。

### 4.2 测试前红线

- 真实动作只允许在 Staging 执行。
- 只允许使用公司自有测试抖音号和受控目标号。
- Production 只检查版本、API 地址、注册与在线状态，不派采集、关注、点赞、回评或私信任务。
- 测试期间禁止人工帮助手机点击抖音流程。发生人工接管后，该检查点必须重新开始。
- 禁止裁剪掉时间、账号或水印的证据。
- License Key、WS token 和其他凭据必须打码。

### 4.3 Golden Path 检查点

| Gate | MAP 对应段 | 核心验收结果 |
|---|---|---|
| GP-00 | 版本与环境 | App 为 `2.1.16`，API 明确为 Staging |
| GP-01 | 安装与绑定 | Agent 注册成功，Agent ID 与后台一致 |
| GP-02 | 运行权限 | 无障碍、截屏、录音三项均已授权 |
| GP-03 | Agent 在线 | 心跳在线，冷启动和重启后可恢复 |
| GP-04 | 抖音小号检测 | 扫描出真实昵称，登录态与手机实际状态一致 |
| GP-05 | 采集发起 | 任务绑定正确租户、Agent 和关键词 |
| GP-06 | 视频采集 | 至少 2 个真实视频，真实 video ID 不少于 15 位 |
| GP-07 | 内容判定 | 至少 1 个视频离开 `pending`；匹配/拒绝与证据一致 |
| GP-08 | 评论与 Lead | 命中时产生真实 Lead，昵称、评论、目标身份可核验 |
| GP-09 | 私信派单 | Lead、assignment、Android Agent 串成同一条数据链 |
| GP-10 | Android 真实私信 | 找对账号、完整输入、只发送一次、收件端真实收到 |
| GP-11 | 自动公开回评 | 当前版本标 `NOT IMPLEMENTED`，不得人工补为 `PASS` |
| GP-12 | 异常恢复 | 断网、离线、过期登录或重启后状态真实且不误发 |
| PROD-RO | Production 冒烟 | 只读确认版本、地址、注册、在线；不触发业务动作 |

### 4.4 “眼”与“手”分开判定

#### “眼”通过条件

- 能定位正确的抖音搜索入口与关键词；
- 能识别至少 2 个真实视频，而非广告占位或伪造 ID；
- 能读取评论昵称和评论正文，Lead 中不得混入 UI 控件描述；
- 能取得目标抖音号，并在进入主页后以“抖音号：目标 ID”再次确认；
- 目标不唯一、找不到或主页 ID 不一致时必须停止，不能继续发送。

#### “手”通过条件

- 能从干净首页开始完成搜索、点击、返回；
- 点击后重新读取页面，不能沿用旧页面状态；
- 已关注或已点赞时不重复点击；
- 私信正文必须与水印话术逐字一致，不得截断；
- 只发送一次；
- 必须看到消息提交后的回执信号，并由受控收件号二次确认收到；
- 找不到私信入口、输入框、发送按钮或回执时必须报失败，不能假报 `sent`。

只有“眼”和“手”都通过，GP-10 才能标 `PASS`。

## 5. 功能需求验收矩阵

| ID | FR | 通过标准 |
|---|---|---|
| FR-01 | APK 安装与绑定 | 无 adb，扫码或输入 License 后完成注册 |
| FR-02 | 环境路由 | Staging 二维码绑定后状态页显示 Staging WS 地址 |
| FR-03 | 权限自检 | App 明确显示无障碍、截屏、录音状态 |
| FR-04 | Agent 注册与心跳 | Agent ID 非空，后台在约定窗口内显示在线 |
| FR-05 | 账号扫描 | 真实抖音昵称上报，掉线后不继续显示可用 |
| FR-06 | 采集任务领取 | 正确 Agent 领取正确租户的任务 |
| FR-07 | 关键词采集 | 任务进入终态，失败时有明确失败分类 |
| FR-08 | 视频结果 | 至少 2 个真实视频 ID 落库 |
| FR-09 | 内容判定 | 至少 1 个视频完成判定，不能全部永久 `pending` |
| FR-10 | 评论 Lead | 匹配视频产生真实 Lead，评论内容具有业务语义 |
| FR-11 | 私信派单 | 派单目标来自本轮真实 Lead，不是人工固定数据 |
| FR-12 | 安卓私信执行 | 精确找人、输入完整、发送并确认真实收到 |
| FR-13 | 结果回传 | `sent / limited / failed` 与真实手机结果一致 |
| FR-14 | 自动公开回评 | 当前版本没有执行入口，标 `NOT IMPLEMENTED` |

## 6. 非功能需求验收矩阵

| ID | NFR | 通过标准 |
|---|---|---|
| NFR-01 | 任务时限 | 采集在 5 分钟内终态；内容判定最多观察 3 分钟 |
| NFR-02 | 单 Lead 熔断 | 单个私信目标超过 90 秒必须停止并报错 |
| NFR-03 | 私信频控 | 同一设备 10 分钟内最多真实发送 3 条 |
| NFR-04 | 关注频控 | 每小时最多新增关注 10 次 |
| NFR-05 | 点赞频控 | 每小时最多新增点赞 15 次 |
| NFR-06 | 可恢复性 | App 冷启动、Agent 重启、短时断网后能恢复心跳 |
| NFR-07 | 可观察性 | 失败能区分环境阻塞、采集错误、账号错误和平台限制 |
| NFR-08 | 数据质量 | Lead 不含按钮名、坐标、节点描述等 UIA 垃圾数据 |
| NFR-09 | 证据完整性 | 手机侧、后台侧、收件端三方时间和任务可关联 |
| NFR-10 | 安全性 | Production 不执行写动作；证据不泄露凭据和个人信息 |

## 7. Invariant 铁律

任一 Invariant 失败，整轮立即标 `FAIL`，不能用其他检查点通过来抵消。

| ID | Invariant |
|---|---|
| I-01 | Staging 与 Production 环境不能串；以 App API 地址为最终依据 |
| I-02 | 租户、Agent、任务、Lead、assignment 必须属于同一条真实链 |
| I-03 | 任务不得读取、修改或触达其他租户的数据 |
| I-04 | video ID 必须是真实抖音 ID，禁止本地随机 ID 或占位值 |
| I-05 | 目标抖音号必须精确匹配；主页复核不一致立即停止 |
| I-06 | 点击发送按钮不等于成功；无回执、无收件端确认不得标 `sent` |
| I-07 | 同一水印话术不得重复发送；出现重复消息立即失败 |
| I-08 | `limited` 不得展示或落库为“已私信” |
| I-09 | Agent 或小号离线、登录过期时不得强行派发 |
| I-10 | 一个小号失效不得连坐停用同设备的其他小号 |
| I-11 | 旧扫描或旧评论数据不得覆盖更新的数据 |
| I-12 | 人工接管后的结果不得作为 Agent 自动化通过证据 |
| I-13 | 手工公开回评不得把 FR-14 从 `NOT IMPLEMENTED` 改成 `PASS` |
| I-14 | Production 不得产生新的采集、关注、点赞、回评、私信或 Lead 测试数据 |

## 8. 证据包设计

每轮验收建立一个目录：

`YYYYMMDD-HHMM_测试人_手机型号_AgentID后8位`

目录必须包含：

1. `00-验收单.md`：版本、环境、账号、任务和结论。
2. `01-Agent状态页.png`：API、Agent ID、权限状态。
3. `02-账号扫描.png`：手机真实账号与后台扫描结果。
4. `03-采集开始.mp4`：任务发起到手机自动拉起抖音。
5. `04-视频与判定.png`：任务 ID、真实视频 ID、判定状态。
6. `05-Lead.png`：昵称、评论、水印前的目标身份。
7. `06-私信执行.mp4`：从抖音首页开始到消息提交，连续录屏、不得剪辑。
8. `07-发送端.png`：完整水印消息和时间。
9. `08-收件端.png`：受控目标号收到同一水印和时间。
10. `09-异常恢复.mp4`：选定异常用例的恢复过程。
11. `10-缺陷单.md`：所有失败、阻塞和未实现项。

录屏中可以遮挡无关个人消息，但不得遮挡目标抖音号、水印话术、动作顺序和时间。

## 9. 打标与总判定

### 9.1 单项状态

- `PASS`：产品自动完成动作，且所有规定证据齐全。
- `FAIL`：产品行为、数据或结果错误，或违反任一 Invariant。
- `BLOCKED`：外部条件导致无法执行，例如测试号被平台封禁、测试网络不可用。必须写明阻塞责任人与复测条件。
- `NOT IMPLEMENTED`：当前版本不存在该产品能力。

禁止使用“基本通过”“大概正常”“偶现先过”“人工操作后通过”等模糊状态。

### 9.2 总结论

正式报告必须同时给出两个结论：

1. **Android 私信子链结论**：GP-00 至 GP-10 与 GP-12 全部通过时可标 `PASS`。
2. **Path 2 完整 MAP 结论**：必须包括自动公开回评。当前 FR-14 / GP-11 为 `NOT IMPLEMENTED`，因此当前版本固定为 `FAIL — 未达到完整 Golden Path`。

`BLOCKED` 不等于 `PASS`。阻塞解除后必须重新执行受影响的 Gate。

## 10. 缺陷严重级别

| 等级 | 定义 | 示例 |
|---|---|---|
| P0 | 串环境、串租户、错人误发、重复发送、Production 写入 | Staging 手机连接 Production 并真实发送 |
| P1 | Golden Path 中断或假成功 | 后台标 sent 但收件端未收到 |
| P2 | 可恢复失败或状态误导 | Agent 已离线但后台仍显示可用 |
| P3 | 不影响结果的展示与文案问题 | 状态提示文字不清楚 |

P0/P1 出现后，本轮立即停止，不继续批量发送。保留现场证据并通知负责人。

## 11. 正式 SOP 的交付形式

最终员工执行版将包含：

- 一页式测试前检查表；
- GP-00 至 GP-12 的逐步操作卡；
- Production 只读冒烟卡；
- FR/NFR/Invariant 勾选矩阵；
- 证据目录模板；
- 缺陷单模板；
- 最终验收报告模板；
- 当前版本已知缺口声明。

文档不包含产品代码修改、自动公开回评的替代实现，也不把旧飞书链路写回现役 MAP。
